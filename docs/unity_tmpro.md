# UnityでTMProを用いたフォント管理の方法
(下書きなのでざつめ。ちゃんと出す時に清書します)


## はじめに
ここではUnityで(やや)面倒なTextMeshProを用いたフォントのセットアップから注意点までの解説です。

> [!NOTE]
> Unityのバージョン 6000.3.24f1
> 記事内で記載しているコードは生成AIで作成したコードを含みます。

## そもそもなんでフォントデータ用意しないといけないの
TMProのデフォルトであるフォントが日本語対応してなくて豆腐になってしまうから。後見た目的にもね。

## フォントのダウンロード
googleフォントから適当にDLしてプロジェクトに.ttfを配置。otfだと確か作成できない。

## 日本語フォントを作ろう
Editor上部にある、`Window->TextMeshPro->Font Asset Creator`を押す。
画面が出てくるので画像のように設定する
(samplesizeは32,paddingは6pxくらいかなぁ)
size: 2048x4096
characterset: custom characters

rendermode: sdf (理由は後述)

さて、charactersetにてcustom charactersを選択したため、どの文字をフォントで描画出来るようにするかを登録しなければなりません。
一般的には[こちら](https://gist.github.com/kgsi/ed2f1c5696a2211c1fd1e1e198c96ee4?h=1)のように、ひらがな・カタカナ・英数字・JIS第一,第二規格・記号までを登録することが多いですが、今回は第二規格は除外して生成します。
というのも、第二規格の漢字は割と使うものもあれば全然使わないだろというものも多く、データが肥大化するリスクと見合いません。このままだと本当に表示したい文字が表示できなくなってしまうので対処法も合わせて紹介します。
ということで[こちら](https://github.com/blivesta/font-jp-subset/blob/master/characters/all.txt)から、ひらがな・カタカナ・英数字・JIS第一規格・記号の文字リストをコピーし、custom character listの欄にペーストしてください。その後、generate font atlasをクリックするとフォントデータが生成されます。これで晴れて日本語フォントが使える！

## 画質が荒いぞ..
TMProではフォントが潰れてしまったように見えることも多くあります。
その場合はsamplesizeを上げたりpaddingの値を調節したりして収めましょう。paddingの値はsamplesizeの1~2割程度が良いです(px指定しよう)。装飾をする場合は2割程度、しない場合は1割程度。
生成時にMissing Charactersがある場合はcustom character listに記載した文字が該当のフォントファイルに週力されていないことを意味します。
Execluded Charactersがある場合は範囲が足りていません。2048x4096から変更するかsamplesize/paddingの値を小さくしましょう。

さて、rendermodeでsdfを指定しましたが、日本語(漢字)のように細かい部分が多い文字に関してはsdfの後ろに数字がつくモードのほうが好ましいです。sdf16や32だときれいに描画できますがその分負荷は上昇します。そのため一度Atlasを生成した後保存せずにsdf16や32に変えてから再度生成しましょう。というのも私の環境限定なのかもしれませんが、最初からsdf16や32といったきれいなもので生成してしまうとうまく生成されないことや、UnityEditorがクラッシュしてしまうことがあるので一度軽量なsdfで生成してからsdf16や32で生成するとそのデータを再利用しているのかクラッシュせずに正常に作成が行なえます。sdf16や32にした場合はデータ量が増えるためatlasの作成にめちゃ時間かかるので注意を。

## 登録していない文字も描画したーーーーい
今回は第一規格まで設定したので、第二~第四規格の漢字はそのままの方法でやると描画されず豆腐になってしまいます。これだととても困りますし、かと言って使う文字だけ抽出して再度生成、、は手間ですし時間もかかってしまいます。そこでFallbackAssetと呼ばれるものを設定します。
生成したfontの.assetファイルを右クリックして、`Create->TextMeshPro->FontAsset->SDF`を選択し新たなデータを作成してください。
生成されたものをクリックして、`GenerationSettings`の欄を元のものと同じにしてください。その後AtlasPopulationModeをDynamic(動的生成)に、MultiAtlasTextures(枠が足りなくなった時に自動で枠を拡張)にチェックを押してください。その後Applyを押す。
設定が終わったら最初に設定したfontの.assetをクリックし、FallbackFontAssetsという欄があるのでそこに先ほど作成したフォントを登録してください。
これで、登録されていない文字が描画された際にリアルタイムで不足分を生成してくれます。第二規格で有名な漢字といえば(?)`鬱`があるのでフォントを設定した状態で鬱をセットすると、fallbackassetの方に`鬱`が生成され、豆腐も解消された状態で表示されると思います。これで解決！

一応dynamicなので動的生成です。あまりにも量が多いと負荷を無視できなくなるので、頻繁に表示するものや絶対表示するだろうものはfont asset作成時に追加で登録しておいたほうが負荷軽減的に良いです。あくまでも手間を抑えつつ現実的な方法で実装している形です。

## gitで管理する際の問題
しかしこのままだと１つ問題があります。Fallbackassetは足りないものがあれば勝手に追加されます。この場合、Prefabやあらかじめ異シーンに置いているUIに採用しているtextに不足分の文字を描画している分には更新があっても問題ありませんが、ゲーム中で動的に生成されるテキストや、新たに変更してFallbackに登録される文字が増えた時にデータが更新されてしまうのでgitの追跡対象になります。
追跡対象になると、異なるブランチでfallback分の文字をそれぞれ追加されてしまった時に競合が起きる可能性がありますし、頻繁に更新ログもでてしまうのでgitのcommitログが荒れる原因にもなるのでなるべく対策しておきたいです。gitiggnoreに追加するとそもそもそのデータを他人に渡さないといけない手間も増えますし、、
そこで下記のコードを作成します。場所自体はどこでもよいのですが、Editorというフォルダを作りその中にこのコードを.csで作成してください。私はFonts内にフォントデータを管理しているのでここにEditorというフォルダを作り配置しています。
```
TMPAssetCleaner.csのコード
```
注意点として、アセット名で検索をかけているので、そこに記載している命名規則でないと検知されずに動作しないといけないことには注意してください。
コードの詳細部分はコメントアウトに書いてあるとおりなので割愛しますが、実行中のみ反映されるようにし、保存やビルド時にクリーンな状態を保つことで元ファイルに実質的に更新がおきず、git側で更新判定がなされないので実質的に追跡しないことができます。このようにすれば無駄な手順を踏まずとも、競合に苦しむこともなくフォントデータの管理ができます。
