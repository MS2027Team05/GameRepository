## PullRequest Templateについて
PR出す時にフォーマット整備できます。
現状はプロジェクトのルート階層に`pull_request_template.md`を配置すれば反映されます。mdで記載した内容がそのまま反映されるので細かいことはそこまで考えなくて良さげ。
PRを出してもらった時に確認する人の負担を減らしたいなら整備しておくと少しだけ幸せになるかも。

## GitLFSについて
GitとGitHubにはサイズ制限があるがGitLFSを使用することである程度緩和できる。仕組みとしてはファイルデータをGitHubにそのまま上げるのではなくファイルの場所だけを保存しておき、実際のデータは他の場所に保存するもの。デフォルトだと提供されているストレージしか使えないが設定するとGDrive等連携できるらしい(ただしデフォルトから変更するとGitHubで対象にした拡張子のファイルがpreviewできなくなるので、一長一短)
ゲームを作るならなるべく有効にしておきたい。プロジェクト途中で導入するとやや面倒なので、最初の段階で導入できるなら導入したい。
まずはダウンロード: [windows](https://git-lfs.com/)
最近のIDEやgitをインストールする時にデフォルトでチェックが入ってることも多いらしいので既に入ってるかも。

プロジェクトの階層に移動してgitbashに`git lfs install`を実行。これでセットアップが完了。
その後、`git lfs track ".*拡張子"`を実行することで`.gitattributes`ファイルが作成される。このファイルを確認してどのファイルをLFS管理下にするか確認/設定しよう。
gitattributesを単体でコミットすると反映。

対象ファイルを追加してpushし、GitHub上で該当のファイルを見ると`Stored with Git LFS`の文字が出るはずです。
ちなみに途中のプロジェクトに入れる場合はそのままでも動くには動くのですが、過去のコミットはそのまま画像の状態で処理されるので、LFS導入前のコミットに対しても適応したい場合は`git lfs migrate`コマンドを実行する必要があります。ただ過去のコミットに対しても変更を適応するため、差分が取れなくなってしまいます。ブランチを切っている場合はmasterやmainブランチに対してforce pushを行なう必要がありますし、他のデバイスや人が既にcloneしている場合は差分の比較ができなくて正常にデータを取得できないので、一度ワークスペースを削除して再度cloneする必要があります。
